# Deploying the demo

| Part | Host | Free-tier notes |
|---|---|---|
| Postgres | **Neon** | Free, doesn't expire, scales to zero |
| API (FastAPI + models) | **Render**, Docker, from `render.yaml` | Sleeps after 15 min idle; the first request then takes about a minute |
| Web (Next.js) | **Vercel** | No cold starts for pages; API calls wait for Render to wake |

Everything uses synthetic data. Don't put real patient information into the demo.

## 1. Neon (database)
1. Create a project at neon.tech, in a region near Singapore if one is offered.
2. Copy the **connection string**. Keep the `?sslmode=require` at the end. The API accepts `postgres://…` as-is and adds the driver itself.

## 2. Render (API)
1. On render.com, choose **New → Blueprint** and pick this GitHub repo. Render reads `render.yaml`.
2. When prompted, set:
   - `DATABASE_URL`: the Neon connection string.
   - `SEED_PASSWORD`: a password for the demo accounts. The sign-in page's demo buttons use `demo-password-123`, so use that, or change `DEMO_PASSWORD` in `apps/web/src/app/(auth)/login/login-form.tsx`.
3. Deploy. On first boot the container:
   - runs `alembic upgrade head`;
   - seeds about 80 synthetic patients, because `SEED_ON_START=true` and the database is empty;
   - starts uvicorn on Render's `$PORT`.

   `JWT_SECRET` is generated by Render. The API refuses to start in production without one.
4. Check `https://<your-service>.onrender.com/health`. It should list the three models.

Later deploys happen automatically, but only after GitHub CI passes (`autoDeployTrigger: checksPass`).

## 3. Vercel (web)
1. On vercel.com, choose **Add New → Project**, import the repo, and set **Root Directory** to `apps/web`. The framework is detected as Next.js.
2. Environment variables:
   - `API_URL` = `https://<your-service>.onrender.com`
   - `COOKIE_SECURE` = `true` (auth cookies become Secure and HSTS is sent)
3. Deploy. Your public URL is the demo link for the README and résumé.

## Before sharing the link
- Open the site once to wake the API, then try each demo role.
- Free Render instances sleep. If a reviewer sees "service unavailable", it's waking up, so a retry after a minute works.
- Change the README's "Live demo" link to your Vercel URL.

## Production gaps (not needed for a demo)
- **Login throttling** is per process (fine for one instance). Use Redis for several instances.
- **No refresh-token revocation list.**
- **No encryption at rest beyond the provider's defaults.**
- **No formal compliance review** (HIPAA / India DPDP).
